# 期刊与会议数据快照

`manifest.json` 是当前快照入口，插件 Preload、期刊 MCP 和小程序素材生成脚本均从它解析数据位置。

当前目录：`2026-v1/`。

| 数据 | 版本 | 指标年 | 条数 |
| --- | --- | --- | --- |
| journals.json.gz | 项目现有 JCR 2026 快照 | 2025 JIF | 22,643 |
| ccf.json.gz | CCF 第七版（2026.3） | 不适用 | 677 |

`2026-v1` 是仓库的配套快照版本，不是插件版本。`organizedOn` 仅表示目录整理日期，不是数据发布或抓取日期。清单记录 SHA256、记录数和版本标注，数据内容未重排、未重新压缩。

## 更新规则

1. 新数据建新目录，如 `2027-v1/`；同年修订可用 `2026-v2/`。CCF 按官方版次更新，不假设每年都有新版。
2. JCR 的发布年份与 JIF 指标年分别记录。版本声明以实际获得的数据为准。
3. CCF 的 `k` 是该配套 JCR 的行下标。更换 JCR 或重排记录时必须重建／核验映射，不能直接沿用旧下标；`linkedJcrSha256` 锁定绑定的 JCR 内容。
4. 更新 manifest 的路径、版本、哈希、条数，及 pack.sh 的显式清单。同步浏览器扩展的两个 gzip，按新 manifest 重建小程序派生数据，核验三端检索。
5. 小程序 `utils/dataset.js` 固定下载 `assets/data/journals/2026-v1/journals.json.gz`，缓存名也包含快照版本；CCF 通过 `data/ccf.js` 内置。根目录两份 gzip 已删除。发布时需先确保远程新路径可用，再发布使用新路径的小程序；旧客户端未缓存数据时仍会访问旧地址。
6. 安装包只包含 manifest 与当前版本数据，不包含历史快照。此处路径调整不改变期刊 MCP 快照 ID 的文件名哈希输入。

清理历史数据须先确认公开下载引用及旧客户端支持范围。
